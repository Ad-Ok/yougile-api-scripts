# Пример файла для импорта задач в Yougile

Этот файл демонстрирует формат для импорта задач и подзадач с различными вариантами форматирования.

## Задача 1: Настройка API интеграции

Интегрировать систему с внешним API для получения данных в реальном времени.

**Требования:**
- Поддержка REST API
- Обработка ошибок и retry логика
- Логирование всех запросов
- Кеширование ответов

**Технический стек:**
- Python 3.11+
- requests / httpx
- redis для кеша

### Подзадача 1.1: Создать базовый HTTP клиент

Разработать класс для отправки HTTP запросов:

```python
class APIClient:
    def __init__(self, base_url, api_key):
        self.base_url = base_url
        self.api_key = api_key
    
    def get(self, endpoint):
        # Реализация GET запроса
        pass
```

**Функционал:**
- Методы GET, POST, PUT, DELETE
- Автоматическая авторизация
- Timeout настройки

### Подзадача 1.2: Добавить retry механизм

Реализовать автоматические повторные попытки при ошибках:

1. Использовать библиотеку **tenacity** или **backoff**
2. Настроить экспоненциальную задержку
3. Максимум 3 попытки
4. Логировать каждую попытку

**Исключения для retry:**
- 429 (Rate Limit)
- 500, 502, 503 (Server Errors)
- Timeout ошибки

### Подзадача 1.3: Настроить кеширование

Добавить Redis кеш для популярных запросов:

- TTL: 5 минут для списков
- TTL: 1 час для детальных данных
- Cache key: `api:endpoint:params_hash`

## Задача 2: Оптимизация производительности базы данных

Провести анализ и оптимизацию медленных запросов к PostgreSQL.

**Цель:** Снизить время выполнения запросов на 50%.

**Проблемные области:**
- Запросы без индексов
- N+1 проблемы в ORM
- Большие JOIN операции
- Отсутствие партиционирования

### Подзадача 2.1: Добавить недостающие индексы

Проанализировать `pg_stat_statements` и создать индексы:

```sql
-- Индекс для поиска по email
CREATE INDEX idx_users_email ON users(email);

-- Составной индекс для фильтрации
CREATE INDEX idx_orders_user_status 
ON orders(user_id, status, created_at DESC);

-- Частичный индекс для активных записей
CREATE INDEX idx_active_subscriptions 
ON subscriptions(user_id) 
WHERE status = 'active';
```

### Подзадача 2.2: Исправить N+1 запросы

Использовать `select_related` и `prefetch_related`:

**До оптимизации:**
```python
# Генерирует N+1 запросов
for order in Order.objects.all():
    print(order.user.name)  # Отдельный запрос для каждого user
```

**После оптимизации:**
```python
# Один JOIN запрос
for order in Order.objects.select_related('user'):
    print(order.user.name)
```

### Подзадача 2.3: Настроить партиционирование таблицы логов

Разбить большую таблицу `logs` по датам:

1. Создать партиции по месяцам
2. Настроить автоматическое создание новых партиций
3. Архивировать старые данные (>6 месяцев)

**Выгода:** Ускорение запросов на 10x для недавних данных.

## Задача 3: Написать документацию для новой фичи

Создать пользовательскую документацию для функционала экспорта отчетов.

**Целевая аудитория:**
- Конечные пользователи (не технические)
- Администраторы системы

**Формат:**
- Markdown файлы
- Скриншоты с аннотациями
- Видео-гайды (опционально)

### Подзадача 3.1: Написать пошаговую инструкцию

Описать процесс создания и экспорта отчета:

1. Войти в раздел "Отчеты"
2. Нажать кнопку "Создать отчет"
3. Выбрать тип отчета из списка:
   - Финансовый отчет
   - Отчет по задачам
   - Аналитика пользователей
4. Настроить фильтры (период, категории)
5. Выбрать формат экспорта (PDF, Excel, CSV)
6. Нажать "Экспортировать"

**Важно:** Процесс экспорта может занять до 2 минут для больших датасетов.

### Подзадача 3.2: Добавить раздел FAQ

Ответить на типичные вопросы:

**Q: Можно ли автоматизировать создание отчетов?**
A: Да, настройте расписание в разделе "Автоматизация" → "Планировщик отчетов".

**Q: Какой максимальный период для отчета?**
A: Последние 2 года. Для более старых данных обратитесь в поддержку.

**Q: Поддерживается ли групповой экспорт?**
A: Да, можно выбрать несколько отчетов и экспортировать их одним архивом.
